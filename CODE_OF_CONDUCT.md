# Code of conduct

<!-- SPDX-License-Identifier: AGPL-3.0-only -->

Be straightforward and be kind. Discuss the code, not the person. A disagreement about a
design decision is useful; a comment about someone is not.

In this project specifically:

- An objective statement about a design choice is welcome. Attacking another open-source
  project is not.
- "This increases streaming risk" and "this turns one request into many" are the reasons a
  change gets declined. Those reasons must be stated, not implied.
- Reports about a bug are read as reports about a bug. A test that fails is information, not
  an accusation.

This project follows the [Contributor Covenant 2.1](https://www.contributor-covenant.org/version/2/1/code_of_conduct/).
Issues about conduct go to the repository owner through a private issue or a private
security advisory. The maintainer responds within a week and can ask a contributor to leave
the project after a repeated or serious breach.
